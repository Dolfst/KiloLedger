# KiloLedger

[English](README.md) · [Русский](README.ru.md)

**Учёт расходов на автомобиль для Windows, Android и Windows Mobile.**

KiloLedger ведёт заправки, ремонт, прочие расходы на машину и коммунальные платежи для одного или нескольких автомобилей. Компьютер на Windows, телефон на Android и КПК на Windows Mobile используют одни и те же текстовые файлы, один номер версии и общий логотип — красный круг с машинкой. Приложения работают без сети. Облако необязательно: это ваша собственная таблица Google.

Текущая версия: **1.39.3**, файл [`VERSION`](VERSION). Готовые сборки лежат в [`dist/download`](dist/download).

Название продукта — **KiloLedger**. Каталоги проектов, пространства имён и часть имён файлов по-прежнему `Alfa156` (на Android идентификатор `com.kiloledger.app`).

## Зачем это приложение

Три клиента решают одну задачу: записать, во что обошёлся автомобиль, увидеть стоимость километра и расход топлива и перенести журнал на другое устройство без обязательной учётной записи. КПК не ходит в Google напрямую. Он обменивается данными с Android по локальному Wi-Fi либо через папку или ZIP, которые открывает компьютер.

В репозитории нет установщика для ПК и нет карточки магазина приложений. Запускается готовый файл, APK или `.exe` для Windows Mobile.

## Возможности

Это есть в трёх клиентах и описано в [`docs/snapshot-schema.md`](docs/snapshot-schema.md):

- Несколько автомобилей, паспорт (год, номер, VIN, объём бака, примечание) и автомобиль по умолчанию.
- Заправки: дата, пробег, литры, стоимость, цена за литр, комментарий, признак полного бака, цель, АЗС или бренд.
- Ремонт и ТО со своим списком категорий.
- Прочие расходы со своим списком категорий.
- Одна коммунальная запись на месяц: коммунальные платежи, электричество, газ, стационарный телефон, домашний интернет, налог на аренду и аренда жилья.
- Поездки: начальный и конечный пробег, цель и водитель. Пробег строки равен `endKm − startKm`.
- Заметки, напоминания по дате (страховка, техосмотр или своё) и шаблоны заправки, ремонта и прочего расхода.
- Фото чеков: `Receipts/{recordId}.jpg`. Android и Desktop умеют прикрепить и удалить фото. КПК открывает или удаляет уже сохранённое фото выбранной записи.
- Сводка: график за 12 месяцев, стоимость километра, расход л/100 км между полными баками, итог за год, сравнение автомобилей и сравнение периодов.
- Оценка до следующего ТО по недавним показаниям одометра (средний км/день и срок до замены масла и ремня ГРМ).
- Мягкий месячный бюджет (`budget_month`, предупреждение при `budget_warn_pct`, по умолчанию 80). Коммунальные платежи в эту автомобильную сумму не входят.
- Отчёт за период. Desktop сохраняет `.txt` или `.html` и печатает. Android делится текстом или HTML. КПК сохраняет текст и может сохранить HTML.
- Поиск, фильтры, поиск дубликатов, проверка пробега и проверка целостности данных.
- Полные копии ZIP или папкой, файл `snapshot.json` и страховочная копия перед восстановлением.
- Локальная синхронизация по Wi-Fi между Android и КПК и необязательная синхронизация с Google Таблицами на Android и Desktop.
- Языки интерфейса: русский, английский, испанский, французский и немецкий. Словари встроены в exe Desktop и в ресурсы Android. Язык по умолчанию — русский.

В новой базе интервалы ТО такие: масло 10 000 км (предупреждение за 1 000 км), ремень ГРМ 60 000 км (предупреждение за 5 000 км). Код валюты по умолчанию — `BYN`. Всё это лежит в `settings.dat` и меняется в приложении.

## Технологии

| Клиент | Каталог | Стек |
| --- | --- | --- |
| КПК, Windows Mobile | `Alfa156/Alfa156` | .NET Compact Framework 3.5, Windows Forms, Pocket PC |
| Android | `Alfa156.Android` | .NET 10 (`net10.0-android`), приложение `com.kiloledger.app`, минимум Android 6.0 (API 23) |
| Windows, ПК | `Alfa156.Desktop` | .NET Framework 4.8, Windows Forms |
| Мост к Google Таблице | `google-sync/Alfa156Sync.gs` | веб-приложение Google Apps Script |

Одинаковая предметная логика сознательно скопирована в каждый клиент. Изменение поведения или формата `.dat` нужно вносить во все клиенты, которых оно касается.

Публикуемые сборки Android — APK для ARM64. GitHub Actions подписывает их ключом `Alfa156.Android/alfa156-upload.keystore`.

## Требования

Чтобы **запустить** готовую сборку:

- **Android:** Android 6.0 или новее, 64-bit ARM. Если система спросит, разрешите установку из файлового менеджера.
- **Windows:** .NET Framework 4.8. Файл `.exe` не установщик.
- **Windows Mobile:** на устройстве нужен .NET Compact Framework 3.5. Файл копируют через Windows Mobile Device Center или ActiveSync. Zip для КПК в `dist/download` описан там как приложение вместе с CAB CF 3.5.

Чтобы **собрать**:

- КПК на Windows: `build/build-kpk.ps1`, `ResGen.exe` и `csc.exe`, справочные сборки уже лежат в `build/cf35/WindowsCE`. Вместо этого можно открыть `Alfa156/Alfa156.sln` в Visual Studio 2008 с Windows Mobile SDK.
- КПК на Linux или macOS: Mono (`mono-devel`) и `./build/build-kpk.sh`.
- Desktop на Windows: MSBuild и targeting pack .NET Framework 4.8.
- Desktop на Linux, как в заметках репозитория для агентов: .NET SDK и `FrameworkPathOverride` на справочные сборки Mono 4.8.
- Android: .NET 10 SDK, workload Android, JDK 17 и Android SDK. В CI ставятся платформа 36 и build-tools 36.0.0.

Smoke-проверкам нужен Python 3. В CI стоит Python 3.12. Устройство и эмулятор не нужны.

Те же файлы прикреплены к скользящим релизам [`android-latest`](https://github.com/Dolfst/KiloLedger/releases/tag/android-latest), [`desktop-latest`](https://github.com/Dolfst/KiloLedger/releases/tag/desktop-latest) и [`kpk-latest`](https://github.com/Dolfst/KiloLedger/releases/tag/kpk-latest). Workflow **Android APK**, **Desktop EXE** и **KPK EXE** пересобирают их при push в соответствующий проект или в `VERSION`. Их можно запустить вручную на вкладке Actions.

На КПК новый `KiloLedger-<версия>-KPK.exe` нужно один раз запустить. Он переписывает ярлык в меню «Пуск», чтобы тот указывал на эту сборку.

APK с другой подписью или старая установка с другим идентификатором приложения поверх не обновляется. Сначала экспортируйте ZIP, удалите приложение, поставьте новый APK и импортируйте ZIP.

### Сборка из исходников

КПК:

```powershell
powershell -ExecutionPolicy Bypass -File build/build-kpk.ps1 -Configuration Release
```

```sh
./build/build-kpk.sh Release
```

Desktop на Windows:

```bat
msbuild Alfa156.Desktop\Alfa156.Desktop.csproj /p:Configuration=Release /p:Platform=AnyCPU
```

Результат: `Alfa156.Desktop\bin\Release\Alfa156.Desktop.exe`.

Desktop на Linux, если установлены справочные сборки Mono 4.8:

```sh
dotnet build Alfa156.Desktop/Alfa156.Desktop.csproj --nologo -p:FrameworkPathOverride=/usr/lib/mono/4.8-api
```

Android ARM64, когда заданы `ANDROID_HOME` и `JAVA_HOME` и установлен workload Android:

```sh
dotnet workload install android
dotnet build Alfa156.Android/Alfa156.Android.csproj \
  -t:InstallAndroidDependencies -f net10.0-android \
  -p:AndroidSdkDirectory="$ANDROID_HOME" \
  -p:JavaSdkDirectory="$JAVA_HOME" \
  -p:AcceptAndroidSDKLicenses=True
dotnet build Alfa156.Android/Alfa156.Android.csproj -c Release \
  -p:RuntimeIdentifier=android-arm64 \
  -p:AndroidSdkDirectory="$ANDROID_HOME" \
  -p:JavaSdkDirectory="$JAVA_HOME" \
  -p:AcceptAndroidSDKLicenses=True
```

Подписанный APK лежит в `Alfa156.Android/bin/Release/net10.0-android/android-arm64/`, имя заканчивается на `-Signed.apk`.

## Настройка

Файла `.env` у приложений нет.

| Что | Где |
| --- | --- |
| База КПК | `\My Documents\KiloLedger\` |
| База Android | `files/KiloLedger` в закрытом каталоге приложения (`FilesDir`) |
| База Desktop | Папка, которую выбирает пользователь. **Открыть папку** / **Новая папка** создаёт или открывает каталог `KiloLedger`. Импорт без уже выбранной папки использует `Documents\KiloLedger` |
| Язык интерфейса Desktop | `%AppData%\KiloLedger\language.txt` (и ключ `language` в `settings.dat`, когда база открыта) |
| Google Sync на Desktop | `%AppData%\KiloLedger\google-sync.json` — `scriptUrl`, `token`, `spreadsheetUrl` |
| Google Sync на Android | закрытые настройки `google-sync` (`scriptUrl`, `token`) |
| Секрет Apps Script | свойство скрипта `SYNC_TOKEN`. Отдельный скрипт, не привязанный к таблице, дополнительно требует `SPREADSHEET_ID` |

В `settings.dat` лежат пары вроде `oil_interval`, `oil_warn`, `belt_interval`, `belt_warn`, `currency`, `budget_month`, `budget_warn_pct`, `backup_remind_days`, `default_car`, `reminder_warn_days`, `language` и `snapshot_device_token`.

При сборке Android используются `ANDROID_HOME` и `JAVA_HOME`. Не публикуйте `SYNC_TOKEN`, URL веб-приложения и `google-sync.json`.

Пошаговая настройка Google со скриншотами: [`google-sync/README.md`](google-sync/README.md) и [`GOOGLE_SYNC.md`](GOOGLE_SYNC.md).

## Как пользоваться

**Desktop.** Запустите `.exe`. При первом запуске приложение спрашивает язык и записывает его в `%AppData%\KiloLedger\language.txt`. Папку данных открывают или создают из меню **База**. Разделы: автомобили, заправки, ремонт, прочие, коммуналка, сводка и настройки. Меню **Обмен** — это ZIP, Excel, CSV, мастер импорта и Google (**Google: мастер**, **Google: настройка**, **Синхронизация Google**). В меню **Сервис** есть пункт **О программе**. В карточках настроек — интервалы ТО, валюта, бюджет, напоминание о копии, автомобиль по умолчанию и язык.

**Android.** Закрытое хранилище создаётся при первом запуске. Пустую базу начинают через **Данные → Начать с нуля**: приложение спросит первый автомобиль. Папку с КПК или ZIP импортируют через **Данные → Импорт копии**. Там же экспорт ZIP, синхронизация по Wi-Fi и настройки Google.

**Windows Mobile.** Данные всегда в `\My Documents\KiloLedger\`. Форма спроектирована под ширину QVGA (240 пикселей) и масштабируется под устройство. Меню **Данные** создаёт копию в памяти устройства или на карте памяти и запускает синхронизацию по Wi-Fi.

Расход в л/100 км считается только от полной заправки к следующей полной с большим пробегом. Стоимость километра берёт внесённые затраты и разницу между минимальным и максимальным записанным пробегом. Пропуски и коммунальные платежи она не учитывает.

## Данные и копии

Файлы — текст UTF-8, одна запись в строке, поля разделены `|`. Обратная косая черта экранирует `|` и саму себя. В конце записи стабильный id (`c_`, `f_`, `r_`, `u_`, `e_`, `k_`, `p_`, `m_`, `t_`, `n_`, `j_` или `g_` и 8 шестнадцатеричных знаков). Старые файлы без id читаются. Id назначаются при сохранении. Удаления пишутся в `deleted.dat` (`тип|id|UTC`) и обрезаются до последних 5 000 строк, чтобы следующая синхронизация их не вернула.

Раскладка колонок, `snapshot.json` (`schema` = `kiloledger.snapshot`, `schemaVersion` 1) и отказ от неизвестной схемы заданы в [`docs/snapshot-schema.md`](docs/snapshot-schema.md). Копии старше 1.36.0 без `snapshot.json` по-прежнему допустимы.

Копии на КПК:

- Память устройства: `\My Documents\KiloLedger_LocalBackups\`
- Карта памяти: `\Storage Card\KiloLedger_Backups\ГГГГММДД_ЧЧММСС\`

Перед восстановлением текущие данные сохраняются. Если в старой копии нет папки `Receipts/`, уже лежащие на устройстве фото не выбрасываются. Android перед заменой полного набора пишет `Backups/Safety_…`. Desktop делает то же самое: папка `Safety_yyyyMMdd_HHmmss` рядом с базой.

## Синхронизация

```text
Windows Mobile  ←── Wi-Fi, порт 45816 ──→  Android  ←── Apps Script ──→  Google Таблицы  ←→  Windows, ПК
```

**Android ↔ КПК.** Оба устройства в одной сети Wi-Fi, либо КПК подключён к точке доступа телефона. Интернет не нужен. На Android пункт **Данные → Синхронизация по Wi-Fi** показывает адрес (у точки доступа часто `192.168.43.1`) и шестизначный код. Их вводят на КПК. Полезная нагрузка сначала проверяется во временной папке. Обе стороны показывают предпросмотр слияния и записывают данные только после подтверждения. Перед записью создаётся копия `Safety_`. С версии 1.12 сессия обфусцируется ключом от кода сопряжения (`SYNC2`, а с фото — `KILOLEDGER2R`). Это не TLS. Используйте сеть, которой доверяете. За один сеанс передаётся не больше 50 фото и не больше 2 МБ на файл.

Обмен по Wi-Fi реализован только на Android и Windows Mobile. Компьютер этого протокола не говорит. Bluetooth не используется.

Сначала записи сопоставляются по стабильному id, иначе по естественному ключу (для заправки: дата, автомобиль и пробег). В полезную нагрузку Wi-Fi входят общие `.dat`, на текущих версиях в том числе шаблоны, напоминания, заметки, паспорт автомобиля и поездки.

**Android / ПК ↔ Google Таблицы.** В таблицу вставляют `google-sync/Alfa156Sync.gs`, задают `SYNC_TOKEN` и публикуют веб-приложение от своего имени с доступом «все, у кого есть ссылка». Скрипт забирает и отдаёт автомобили, заправки, ремонт, прочие расходы, коммунальные, категории ремонта и категории прочих. Листы называются `Заправки {авто}`, `Ремонт {авто}`, `Прочие {авто}`, `Коммунальные`, `Справочник` и `Кат. прочих`. Поездки, заметки, напоминания, шаблоны, паспорт автомобиля и фото чеков в эту полезную нагрузку не входят. Стабильные id остаются в локальных `.dat` и в ZIP. Импорт Excel на Desktop дополнительно узнаёт книгу в раскладке Dengi, если имена листов ей соответствуют.

## Проверки

Офлайн-проверки — это `build/verify_*.py`. Они читают исходники и фикстуры. APK они не ставят и Windows Forms не запускают.

```sh
python3 build/run_verifies.py
```

Скрипт запускает каждый `verify_*.py` и завершается с ненулевым кодом, если хоть один упал. Покрыты стабильные id и tombstone, импорт ZIP и CSV, схема снимка, отчёты за период, поездки, бюджет, предпросмотр и повтор синхронизации, а также сторож API Compact Framework (`verify_cf_apis.py`). `verify_version_consistency.py` сверяет поля версии с файлом `VERSION`.

Workflow **Smoke verifies** на GitHub Actions запускает этот набор и `./build/build-kpk.sh Release` на Ubuntu с Mono. Он срабатывает на pull request и на push в `main`, если меняются код приложений, `build/`, `VERSION`, `README.md` или `google-sync/`.

## Состояние и план

Текущая линия — версия 1.39.3. Недавняя работа по Desktop (1.38.3–1.39.3): боковая панель и компактная шапка, отдельные карточки настроек, исправление пустой вкладки «Настройки», встраивание языковых ресурсов в один `.exe` и экран «О программе» со ссылкой на репозиторий на всех трёх клиентах.

Там ещё открыты сверка всех полей версии с файлом `VERSION` и миграции для будущих сущностей (уже существующим строкам id назначается при загрузке). Эти пункты не сделаны, пока `ROADMAP.md` не отмечает их выполненными.

`localization/LOCALIZATION.md` описывает ранний набросок i18n. Пять языков, перечисленных выше, уже встроены в клиенты.

## Поддержка

KiloLedger бесплатный и без рекламы. Репозиторий — [Dolfst/KiloLedger](https://github.com/Dolfst/KiloLedger). Экран «О программе» по-прежнему открывает `https://github.com/Dolfst/alfa#support`; GitHub перенаправляет этот адрес сюда, на якорь `#support` английского [`README.md`](README.md). Этот раздел его повторяет.

- Поставьте звезду [Dolfst/KiloLedger](https://github.com/Dolfst/KiloLedger), если проект полезен.
- Ссылок на платную поддержку (Boosty, Tribute, ЮMoney) в репозитории пока нет. Добавьте их в раздел Support английского README, когда выберете. Приложения уже открывают этот якорь.

Замечания: [github.com/Dolfst/KiloLedger/issues](https://github.com/Dolfst/KiloLedger/issues).

## Участие в разработке

Смотрите [CONTRIBUTING.md](CONTRIBUTING.md) и [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md). Коротко: три клиента и формат `.dat` нужно держать согласованными, на КПК оставаться в API Compact Framework 3.5 и перед завершением запускать `python3 build/run_verifies.py`. Сообщения коммитов в этом репозитории двуязычные — русский и английский.
