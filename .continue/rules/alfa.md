# Правила проекта Alfa 156

- Объяснения давай на русском; имена в коде оставляй в стиле проекта.
- Сообщения коммитов агента пиши на двух языках: сначала смысловое описание по-русски, затем по-английски, например `Исправить проверку импорта / Fix import validation`.
- В репозитории два приложения: Android в `Alfa156.Android/` и старое Windows Mobile в `Alfa156/`. Не смешивай их технологии и требования.
- Android-приложение использует .NET 10 и Android Views. Перед изменениями изучай связанные файлы и сохраняй существующее поведение.
- Данные передаются в текстовых `.dat`-файлах. Не меняй формат, разделители или экранирование без явного запроса.
- Изменения делай небольшими. Не редактируй сгенерированные файлы и содержимое `bin/` или `obj/`.
- После изменений Android-проекта проверяй сборку, если установлены нужные .NET и Android-компоненты.
- Экономь контекст и кредиты: сначала ограниченный `git status` и недавние коммиты, затем только файлы и разделы задачи; независимые проверки объединяй.
- Не перечитывай весь диалог или большие документы без необходимости. Не запускай агента для узкой задачи, которую можно завершить одним проходом.
- Для handoff используй короткий итог: что сделано, коммит, проверки, следующий шаг. Долгую историю сохраняй только в commit/ROADMAP, не в служебных файлах сессии.
