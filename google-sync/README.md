# Синхронизация Alfa156 ↔ Google Sheets

Общий хаб: таблица «Деньги» (или копия с теми же листами).

```text
КПК  ←Wi‑Fi / точка доступа→  Android  ←Apps Script→  Google Sheets  ←→  ПК
```

КПК **напрямую в Google не ходит** — только через Android (Wi‑Fi) или ZIP/папку через ПК.

## Установка скрипта (один раз)

1. Откройте Google-таблицу с листами `Заправки Alfa Romeo 156`, `Ремонт …`, `Коммунальные`, `Справочник`.
2. **Расширения → Apps Script**, вставьте код из `Alfa156Sync.gs`.
3. ⚙ **Project Settings → Script properties**: ключ `SYNC_TOKEN`, значение например `alfa156`.
4. **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. Скопируйте URL веб-приложения.

## ПК (Alfa156 Desktop)

1. Кнопка **Google: настройка** — вставьте URL веб-приложения и token (не URL таблицы).
2. **Синхронизация Google** — сначала pull, затем диалог:
   - добавить записи, которые есть только в Google;
   - удалить локальные, которых нет в Google (по умолчанию **нет**);
   - что делать при отличии одной и той же записи.
3. После подтверждения локальные `.dat` обновляются и уходят в таблицу (push).

Конфиг: `%AppData%\Alfa156\google-sync.json`

После обновления `Alfa156Sync.gs` сделайте **Deploy → Manage deployments → Edit → New version** — иначе на сервере останется старый код без снятия data validation.

## Android

**Данные → Синхронизация Google** — те же URL и token (хранятся в настройках приложения).

## Конфликт записей

На ПК выбор задаётся в диалоге синхронизации. По умолчанию локальная версия сохраняется, записи только из Google добавляются, локальные «лишние» не удаляются.

## Ограничение: id и удаления (с 1.10.0)

Локальные `.dat` хранят стабильные id и `deleted.dat` (tombstones). В Google Sheets / Dengi id **не пишутся** (layout колонок без изменений), поэтому обмен с таблицей по-прежнему key-based. Надёжная передача удалений — по Wi‑Fi Android↔КПК и через ZIP/папку `.dat`, не через Google.

Если push падает с ошибкой про проверку данных в ячейке (например C9) — в скрипте уже есть `clearDataValidations` перед записью; перевыложите deployment.
